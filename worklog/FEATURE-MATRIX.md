## 1. Named Feature Contract — Wave 5 implementation spec (self-contained)

**Feature:** *"reconstructed files with directory structure preserved, containing ONLY deleted files (not currently-existing files), as a post-scan option."* Reference contract: SectorForge (SF §Named Feature Deep Dive). Target verdict today: **PARTIAL** (TS "Verdict on the named feature").

### 1.1 SectorForge's exact observable contract

**(a) Scan-time deleted/live classification, per filesystem** (classification is *index-build-time*, from on-disk evidence; the filter is applied *post-scan at emission time, within the same command*):
- NTFS: MFT record flags bit 0 → `Record.in_use` (`crates/sf-core/src/ntfs/record.rs` `parse_record` line 102, `in_use: flags & 1 != 0`), copied into `IndexEntry { in_use, … }` while `Index::build` sweeps the MFT (`ntfs/mod.rs` lines 70–105); JSON emits the inverse `"deleted": !e.in_use` (`crates/sf-cli/src/recover.rs` `run_files` line 250).
- FAT: directory entry first byte `0xE5` → deleted at parse time (`fat/dir.rs` `parse_fat` line 102, `DELETED: u8 = 0xE5` line 8); children of a deleted directory inherit deletion: `let deleted = r.deleted || parent_deleted;` (fat/mod.rs line 431).
- exFAT: entry-set in-use bit (bit 7 of the type byte) — `let deleted = in_use == 0;` (dir.rs `parse_exfat` line 173); checksum computed as if the bit were set (`set_checksum` lines 132–138).
- ext: live entries vs deleted names in the slack after a live entry's name — `parse_dir` pushes `(ino, name, false)` live and `(ino, name, true)` slack (ext/mod.rs lines 392–409); `in_use: !deleted` (line 496).
- Emission filter: `run_files` builds the **entire** index first (`build_index`, recover.rs line 229 — same MFT walk either way), then walks `index.ids()` skipping live entries: `if deleted_only && e.in_use { continue; }` (recover.rs lines 236–243). It is an emission filter, not a distinct scan path.

**(b) GUI presentation (exact UI text and flow):**
- Post-scan, client-side: FileBrowser "Filters" row shows a checkbox labeled exactly **"Deleted only"**, beside **"Recoverable only"** and a "Search by name" box (`gui/src/screens/recover/FileBrowser.tsx` lines 154–160; `setFlag("deletedOnly")` line 146). Any active filter switches the browser from folder view to a **flat whole-partition view**: crumbs "Showing matches from the whole partition." + **"Back to folders"** link (lines 91–99); each flat row shows an "in \<folder\>" link that clears filters and navigates to the file's folder (lines 201–212). Count line: "N matches (of M entries)" / "N items here (M entries in all, D deleted)" (lines 168–172).
- Pre-listing, server-side: a checkbox labeled exactly **"Only list deleted files (quicker on very large volumes)"** above the "List files" button (`gui/src/screens/recover/FilesTab.tsx` lines 54–56; state `deletedOnlyRun`). `startListing()` forwards `deletedOnly: deletedOnlyRun` (`gui/src/store/actions.ts` line 246 → `start_files` appends `--deleted-only`, `gui/src-tauri/src/lib.rs` lines 215–225) and **starts the run in the flat deleted-only view**: `filter: deletedOnlyRun ? { ...NO_FILTER, deletedOnly: true } : NO_FILTER`, comment "A deleted-only run has no live folders to browse through, so start on the flat list of everything it found" (actions.ts lines 239–240).
- Reconstruction step: tick rows or whole folders ("Selecting a folder extracts everything inside it.", FilesTab line 149), set "Extract to", press **"Extract selected"** (FilesTab lines 112–152). Extraction re-lists the source (same `files` pass — contract lines 248–251) and recreates the original tree under the output dir.

**(c) Rooted/Orphaned tree semantics:**
- Parent references (full NTFS file reference = record number + sequence) are primary, not path strings; FAT/exFAT/ext reuse the same `parent_ref` field with the parent's index id (fat/mod.rs line 456; ext line 498).
- **Sequence-aware validation** (`Index::parent`, ntfs/mod.rs lines 126–137): the parent must exist, be a directory, and its current sequence must equal the stored one — **except a deleted parent may be exactly one sequence ahead**, because deletion bumps the sequence: `let same = p.seq == pseq || (!p.in_use && p.seq == pseq.wrapping_add(1));`.
- Recursive walk up the chain (`Index::ancestry` lines 139–156) with guards `chain.len() < 4096 && !chain.contains(&p)` (cycle protection), producing `Ancestry::Rooted(Vec<u64>)` (ids root→record) or `Ancestry::Orphaned(Vec<u64>)` when the chain breaks.
- Path strings are derived (`Index::path` lines 158–174): join rooted-chain names with `/`; `None` for orphans. A deleted folder `/OldStuff` and its deleted child `/OldStuff/inner/memo.txt` keep full original paths (sample `docs/contract-samples/files_deleted_only.ndjson` lines 6–9; contract-smoke.ps1 line 239 "file in deleted folder keeps its path").
- GUI: `FileStore.add(r)` splits the emitted path into `(dir, leaf)`, interns dirs in a shared pool, appends to `kids[dir]` — or `orphans[]` when `path == null` (filestore.ts lines 107–127); orphans grouped under pseudo-folder **"Orphaned files (N)"** (`ORPHANS = ":orphans:"` filestore.ts line 4 — "real folder keys always start with `/`, so this cannot collide").

**(d) Output layout & collisions:**
- Under `--out DIR` (created if missing — recover.rs line 299): original hierarchy recreated from the (possibly deleted) parent chain; `dir_for` recursively creates parents, mapping each volume directory id to `out/<names>` (`extract.rs` lines 160–197, `dir_for` 216–238); `Writer.dirs: HashMap<u64, PathBuf>` memoizes one output dir per folder id (lines 152–158). Deleted folders are created exactly like live ones — deletion affects notes, never layout.
- Orphans: `out/_orphaned/<name> (id N)<ext>` (`ORPHANS: &str = "_orphaned"` extract.rs line 14); orphaned folders keep contents under them; orphan roots get the id suffix so two orphaned "Documents" folders don't merge (`top_name` applies `with_id_suffix` when `chain.first() == Some(&id)`, extract.rs lines 199–207; test line 393).
- Collisions: extraction never overwrites — `target.exists() || self.written.contains(&target)` → retry as `name (id N)` with the suffix **before** the extension (`with_id_suffix`, sanitize.rs lines 66–71: `report (id 42).docx`); if that also collides or hits a directory, the item fails: "an output file with the same name already exists" (extract.rs lines 178–184). Directory collision on disk → id-suffixed dir retry (extract.rs lines 232–234).

**(e) Edge cases (enumerated):** parent record gone → Orphaned → `path: null` → "Orphaned files (N)" group; deleted parent also deleted → link still resolves (seq == stored+1; real-fixture proof `make-ntfs-fixture.ps1` lines 92–96; integration test asserts `out.join("OldStuff/inner/memo.txt").exists()` — `crates/sf-core/tests/ntfs_fixture.rs` line 90); parent reused → seq mismatch → orphaned yet `recoverable == Full` (`ntfs/tests.rs` line 321); broken/cyclic chains guarded (mod.rs line 149); shared parents need no special case (dir memoization); deleted+live same name → `a (id 32).txt` beside live `a.txt` (ntfs/tests.rs lines 375–376) and re-runs never clobber (`rerunning_extract_never_overwrites_a_different_file`, lines 425–435); hostile names → `safe_component` (`\ / : * ? " < > |` + control chars → `_`; trailing dots/spaces → `_`; reserved `CON`/`aux.txt`/`COM1` → leading `_`; UTF-16 truncation to 240 units keeping the extension — sanitize.rs lines 11–62; outputs `_CON`/`__` asserted ntfs/tests.rs lines 395–396); symlink/junction escape inside output → `Writer::make_dir` canonicalizes and refuses "{} leads outside the output folder" (extract.rs lines 240–252); metadata pollution → records 0–15 and `$Extend` never listed (`FIRST_USER_RECORD = 16` mod.rs line 25; `is_listed` rejects EXTEND chains lines 176–185; root extract yields no `$MFT`, tests lines 416–422); deleted FAT dirs parsed strictly (first cluster must begin with `"."`, stop at first implausible entry — fat/dir.rs lines 86–89, 106–110; ≤64 free clusters); deleted exFAT dir w/ reallocated first cluster → empty dir bytes "reused" (fat/mod.rs lines 380–383); deleted FAT files assumed contiguous (fat/mod.rs line 435); ext deleted names w/ reused inode skipped (mod.rs lines 476–479); unknown id → failed item "there is no file or folder with id {id} on this volume" (extract.rs line 162); compressed/EFS → listed partial, extracted **empty** with notes (extract.rs lines 55–65); reused clusters flagged `REUSED_NOTE` (extract.rs lines 85–86); unreadable bytes zero-filled + noted (extract.rs lines 81–83); deleted-only run's `done` counts only deleted entries (files_deleted_only.ndjson line 10; smoke lines 242–244).
**Stated gap even in SF:** no single "export deleted-only tree" button — it is Deleted-only filter + select-all-shown + Extract selected (SF Deep Dive §4).
